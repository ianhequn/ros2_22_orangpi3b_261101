# 编写硬件组件

在 `ros2_control` 中，硬件系统组件是库，由控制器管理器（controller manager）使用 `pluginlib` 接口动态加载。以下是创建源文件、基础测试以及为新硬件接口编写编译规则的逐步指南。

## 准备软件包

如果硬件接口的软件包尚不存在，请先创建它。该软件包应使用 `ament_cmake` 作为构建类型。最简单的方法是上网搜索最新手册。支持此过程的一个有用命令是 `ros2 pkg create`。使用 `--help` 标志获取更多用法信息。还有一个选项可以创建库源文件和编译规则，以帮助后续步骤。

## 准备源文件

创建软件包后，其中至少应有 `CMakeLists.txt` 和 `package.xml` 文件。如果尚不存在，还要创建 `include/<PACKAGE_NAME>/` 和 `src` 文件夹。在 `include/<PACKAGE_NAME>/` 文件夹中添加 `<robot_hardware_interface_name>.hpp`，在 `src` 文件夹中添加 `<robot_hardware_interface_name>.cpp`。可选地添加 `visibility_control.h`，其中定义 Windows 的导出规则。你可以从现有控制器软件包复制此文件，并将名称前缀改为 `<PACKAGE_NAME>`。

## 在头文件（.hpp）中添加声明

注意使用头文件保护。ROS2 风格是使用 `#ifndef` 和 `#define` 预处理指令。（有关更多信息，搜索引擎是你的朋友 :)）。

包含 `"hardware_interface/$interface_type$_interface.hpp"`，如果使用 `visibility_control.h` 也包含它。`$interface_type$` 可以是 `Actuator`、`Sensor` 或 `System`，取决于你使用的硬件类型。有关每种类型的更多细节，请查看硬件组件说明。

为你的 `hardware_interface` 定义一个唯一命名空间。这通常是软件包名，使用 snake_case 写法。

定义 `hardware_interface` 的类，继承 `$InterfaceType$Interface`，例如：

```cpp
class HardwareInterfaceName : public hardware_interface::$InterfaceType$Interface
```

5. 添加一个无参数构造函数，以及以下实现 `LifecycleNodeInterface` 的公共方法：`on_configure`、`on_cleanup`、`on_shutdown`、`on_activate`、`on_deactivate`、`on_error`；并重写 `$InterfaceType$Interface` 定义：`on_init`、`export_state_interfaces`、`export_command_interfaces`、`prepare_command_mode_switch`（可选）、`perform_command_mode_switch`（可选）、`read`、`write`。有关硬件生命周期的进一步说明，请查看该拉取请求；有关方法的精确定义，请查看 `"hardware_interface/$interface_type$_interface.hpp"` 头文件，或 Actuator、Sensor 或 System 的 doxygen 文档。

## 在源文件（.cpp）中添加定义

包含你的硬件接口头文件，并添加命名空间定义以简化后续开发。

实现 `on_init` 方法。在这里，你应该初始化所有成员变量并处理来自 `info` 参数的参数。通常第一行会调用父类的 `on_init` 来处理标准值，例如名称。使用如下方式完成：

```cpp
hardware_interface::(Actuator|Sensor|System)Interface::on_init(info)
```

如果所有必需参数都已设置且有效，并且一切正常，返回 `CallbackReturn::SUCCESS`，否则返回 `CallbackReturn::ERROR`。

编写 `on_configure` 方法，通常在这里设置与硬件的通信，并完成所有设置，使硬件可以被激活。

实现 `on_cleanup` 方法，它执行与 `on_configure` 相反的操作。

实现 `export_state_interfaces` 和 `export_command_interfaces` 方法，在其中定义硬件提供的接口。对于 `Sensor` 类型的硬件接口，没有 `export_command_interfaces` 方法。提醒一下，完整接口名称的结构为 `<joint_name>/<interface_type>`。

（可选）对于 `Actuator` 和 `System` 类型的硬件接口，如果你的硬件接受多种控制模式，请实现 `prepare_command_mode_switch` 和 `perform_command_mode_switch`。

实现 `on_activate` 方法，在其中启用硬件“电源”。

实现 `on_deactivate` 方法，它执行与 `on_activate` 相反的操作。

实现 `on_shutdown` 方法，在其中优雅地关闭硬件。

实现 `on_error` 方法，在其中处理来自所有状态的不同错误。

实现 `read` 方法，从硬件获取状态并存储到 `export_state_interfaces` 中定义的内部变量。

实现 `write` 方法，根据 `export_command_interfaces` 中定义的内部变量值向硬件发送命令。

重要：在文件末尾、命名空间关闭之后，添加 `PLUGINLIB_EXPORT_CLASS` 宏。

为此你需要包含 `"pluginlib/class_list_macros.hpp"` 头文件。作为第一个参数，你应该提供确切的硬件接口类，例如 `<my_hardware_interface_package>::<RobotHardwareInterfaceName>`；作为第二个参数，提供基类，即 `hardware_interface::(Actuator|Sensor|System)Interface`。

## 为 pluginlib 编写导出定义

在软件包中创建 `<my_hardware_interface_package>.xml` 文件，并添加库和硬件接口类的定义，这些必须对 `pluginlib` 可见。最简单的方法是查看 `hardware_interface` 中 `mock_components` 部分的模拟组件定义。

通常，插件名称由软件包（命名空间）和类名定义，例如 `<my_hardware_interface_package>/<RobotHardwareInterfaceName>`。此名称定义了资源管理器搜索硬件接口时的类型。另外两个参数必须与 `<robot_hardware_interface_name>.cpp` 文件底部宏中的定义相对应。

## 编写一个简单测试，检查控制器是否可以被找到并加载

如果软件包中尚无 `test` 文件夹，请创建它，并添加一个名为 `test_load_<robot_hardware_interface_name>.cpp` 的文件。

你可以复制 `test_generic_system.cpp` 软件包中定义的 `load_generic_system_2dof` 内容。

更改复制测试的名称，并在最后一行指定硬件接口类型的地方，填入 `<my_hardware_interface_package>.xml` 文件中定义的名称，例如 `<my_hardware_interface_package>/<RobotHardwareInterfaceName>`。

## 在 `CMakeLists.txt` 文件中添加编译指令

在 `find_package(ament_cmake REQUIRED)` 行下方添加更多依赖。至少包括：`hardware_interface`、`pluginlib`、`rclcpp` 和 `rclcpp_lifecycle`。

添加一条编译指令，创建一个共享库，以 `<robot_hardware_interface_name>.cpp` 文件作为源文件。

为库添加目标包含目录。通常只有 `include`。

添加库所需的 ament 依赖。你至少应添加第 1 项中列出的那些。

使用以下命令导出 pluginlib 描述文件：

```cmake
pluginlib_export_plugin_description_file(hardware_interface <my_hardware_interface_package>.xml)
```

添加目标和包含目录的安装指令。

在测试部分添加以下依赖：`ament_cmake_gmock`、`hardware_interface`。

使用 `ament_add_gmock` 指令为测试添加编译定义。详情请参阅 `ros2_control` 软件包中模拟硬件的做法。

（可选）在 `ament_package()` 之前将你的硬件接口库添加到 `ament_export_libraries`。

## 在 `package.xml` 文件中添加依赖

至少将以下软件包添加到 `<depend>` 标签中：`hardware_interface`、`pluginlib`、`rclcpp` 和 `rclcpp_lifecycle`。

至少将以下软件包添加到 `<test_depend>` 标签中：`ament_add_gmock` 和 `hardware_interface`。

## 编译和测试硬件组件

现在一切就绪，可以使用 `colcon build <my_hardware_interface_package>` 命令编译硬件组件。记得在执行此命令前进入工作空间根目录。

如果编译成功，请 source 安装文件夹中的 `setup.bash` 文件，并执行 `colcon test <my_hardware_interface_package>`，以检查新控制器是否可以通过 `pluginlib` 库找到，并由控制器管理器加载。
